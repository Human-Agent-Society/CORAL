# Study analysis: scripts and evidence set

The scripts that turn the six run directories into the tables the study
reports, and the curated outputs of running them on the runs of record. None
of this calls a model.

**Disclosure.** One researcher built the harness the runs used, read every
evaluator feedback text while building it, knows which arm produced every
artifact, and had seen external quality results before writing the semantic
annotations. Annotations are single-coder with no agreement statistics.
Mechanical fields come from the run records and can be regenerated by anyone
with the run directories.

## Pipeline

```
runs_manifest.json ──► extract.py ──► raw/*.json      (everything the runs recorded, uninterpreted)
                                          │
                                          ├─► build_ledger.py ──► ledger.json, ledger.md, checkpoints.json
                                          ├─► summarize.py ────► summary_tables.md
                                          ├─► validate_annotations.py  (checks evidence/annotations.json against the ledger)
                                          └─► trace_distinctive_responses.py [--browser] ──► out/distinctive_response_audit/
```

| file | what it does |
|---|---|
| `runs_manifest.json` | The runs of record. `extract.py` reads this rather than a list in its own source, so adding a replicate is a data change. Its header says why protocol-1 runs are never pooled with new ones. |
| `extract.py` | Copies each run's versions, events, trigger decisions, proposer contexts, attempts, notes and per-agent commit history into `raw/`. `results/` is expected at the repository root; pass `--results` otherwise. |
| `build_ledger.py` | Mechanical fields for every published criterion: provenance, quote, publication time, feedback-availability lags per agent, eligible commits, score spread. |
| `summarize.py` | Per-agent first→last scores on evolved criteria, seed-criterion trajectories for all six runs, availability timing, checkpoint outcomes. |
| `validate_annotations.py` | Every criterion annotated exactly once, every category from the stated rule set in `coding_protocol.json`. |
| `intervention_identity.py` | The one definition of what identifies a published criterion (`run_id + task + arm + version + name`); every join imports it. |
| `trace_distinctive_responses.py` | Extracts the full chain (window, feedback, subsequent diffs) for the criteria selected for the response audit; `--browser` replays the two museum keyboard before/after pairs with Playwright. |
| `coding_protocol.json` | The annotation axes and their category rules, fixed before coding. |

## Evidence set (`evidence/`)

| file | contents |
|---|---|
| `ledger.md` | Every published criterion (12 adaptive, 10 yoked) with mechanical fields, plus a worked adaptive-versus-yoked trace on the fellowship task. |
| `annotations.json` | The semantic coding of all 22 criteria on five axes, rules first, basis per judgement. |
| `summary_tables.md` | Score trajectories, seed trajectories, availability timing, checkpoint table. |
| `checkpoints.json` | All twelve checkpoint outcomes across the four evolving runs, including the museum yoked abstention. |
| `keyboard_operability_chain.json` | The record behind `../CASE_STUDY.md`: proposal window, cited evidence, per-agent feedback texts, subsequent commits (diff bodies replaced by line counts and file lists). |
| `keyboard_reproductions.json` | The Playwright before/after probes for Ahab's and Davy's repairs: tab sequences and activation results. |

## What is not here

Run directories, proposer contexts, screenshots and Playwright trace archives
are archived outside this repository, as are the behaviour-check protocol and
checker, the blind quality judge and its outputs, and the run-level
diagnostics used while the study was running. `raw/`, `ledger.json` and
`out/` are regenerated from the archive and are not tracked.
